# A4PRINT — подключение сотрудников к Neon Auth (после тестового запуска)

**Статус:** подготовка к безопасному подключению. Ни одного реального сотрудника ещё не активировали.

## Проверенный исходный состав

В Supabase `public.users` — **6 профилей**; к `auth.users` привязаны **4**. Ещё **2** профиля не имеют `auth_user_id`; их нельзя автоматически считать отдельными действующими логинами.

В закрытую таблицу Neon `public.cloud_staff_migration_inventory` перенесены шесть строк сопоставления без паролей, PIN-кодов и ролей. Хеш исходных данных после копирования совпал. Таблицу не могут читать `anonymous`, `authenticated` и роль тестового Render API.

## Безопасная процедура на каждого сотрудника

1. **Администратор подтверждает человека и право доступа** независимо от email. Два профиля без `auth_user_id` отдельно проверяются вручную, без автоматической регистрации.
2. В Neon Auth создаётся учётная запись через штатный поддерживаемый механизм. **Пароль из Supabase перенести нельзя**. Сотрудник устанавливает новый через защищённую процедуру; не присылайте пароль в чат, SQL, GitHub или email.
3. Администратор проверяет, что новая учётная запись Neon принадлежит нужному сотруднику (сессия, подтверждение email/контакт, исключение конфликтов).
4. В закрытом реестре сопоставляется `neon_auth_user_id` с правильным `legacy_profile_id`; нельзя автоматически назначать роли только по совпадению адреса. Сохраняем UUID старого профиля для всех существующих заказов и аудита.
5. Проверяем в новой системе роль, доступ к конкретной организации, административные возможности, видимость чужих заказов, аудит действий. **Нельзя копировать права администратора до проверки.**
6. Только после тестов сессий, выхода/продления, отказа при неправильном пароле и блокировки сотрудника включать веб-форму. Кассовый PIN и локальные очереди остаются отдельным модулем.

## Контрольный SQL для Neon, только чтение

```sql
select migration_status, count(*) as profiles
from public.cloud_staff_migration_inventory
group by migration_status order by migration_status;

select count(*) as unlinked
from public.cloud_staff_migration_inventory
where neon_auth_user_id is null;

select count(*) as email_mismatches
from public.cloud_staff_migration_inventory m
join neon_auth."user" n on n.id=m.neon_auth_user_id
where lower(n.email)<>lower(m.auth_email);

select count(*) as unverified_account_links
from public.cloud_staff_migration_inventory m
join neon_auth."user" n on n.id=m.neon_auth_user_id
where n."emailVerified" is not true;
```

**Ожидаемое состояние до активации:** 4 `AWAITING_PASSWORD_SETUP`, 2 `NEEDS_AUTH_LINK`, 6 без Neon UUID. Любое расхождение — повод остановить переключение.

## Контроль разрешений

- `cloud_staff_migration_inventory` не имеет GRANT даже для `a4print_cloud_probe`. Серверный тестовый API не должен видеть письма сотрудников.
- `cloud_staging_login_aliases` содержит только вымышленный `staging_operator` с `example.com`; его не использовать для настоящих сотрудников.
- Neon Auth: свободная регистрация выключена; сброс пароля отзывает старые сессии.
- Render: `STAGING_AUTH_PROBE_ENABLED=false`; реальная касса и административная авторизация отключены.
- Не использовать `SUPABASE_SERVICE_ROLE_KEY` как секрет для Neon. Neon Auth и Supabase Auth не взаимозаменяемы.

## Программа обязательных проверок перед запуском

- Новая сессия после корректного пароля; отказ для неправильного логина/пароля.
- Истечение, обновление и отзыв сессий; запрет доступа отключённым сотрудникам.
- Ролевой доступ: сотрудник, управляющий, администратор, только собственная организация.
- Касса: PIN отдельно, открытие/закрытие смен, возврат, отложенный чек и недублирующая синхронизация.
- 3D-ARTPRINT: загрузка STL/G-code, файлы заказа в производство, фото, таймер, права оператора.
- ЦУИМ: покупатели/продавцы отдельно от HUB; никакого автоматического доступа к чужим профилям.
- Мониторинг нагрузки Neon и план отката на старую систему.

## Подтверждённый технический тест

[Успешный прогон CI c вымышленной учётной записью](https://github.com/nyaganmaksimov-sys/a4print-hub/actions/runs/42265496569) проверил sign-up/sign-in/get-session и подтверждение короткого логина в Render; реальные пользовательские сессии **не выдавались**. Временный маршрут затем отключён.

Официальный справочник: [Neon — перенос из Supabase](https://neon.com/docs/auth/migrate/from-supabase).
