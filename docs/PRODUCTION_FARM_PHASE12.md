# Этап 12: плановое ТО в автоматическом контроле производства

## Что сделано

Автоматический контроль производственной фермы теперь использует уже существующий календарь обслуживания оборудования `equipment_maintenance_plans` и не создаёт параллельный справочник ТО.

### Сигналы обслуживания

- `SERVICE_OVERDUE` срабатывает, если просрочено либо общее `equipment_assets.next_service_date`, либо любой активный регламент обслуживания.
- `SERVICE_DUE` срабатывает для общего ТО по глобальному порогу `production_monitor_settings.service_due_days`.
- Для повторяющихся регламентов `SERVICE_DUE` использует индивидуальное поле `remind_before_days` каждого плана.
- После выполнения регламента существующая функция `complete_equipment_maintenance_plan()` переносит `next_due_date` на следующий интервал, поэтому сигнал автоматически исчезает или переносится на новую дату.

### Интерфейс

В окне `🚨 Контроль` карточка оборудования показывает ближайшую дату обслуживания. Если ближайшим является повторяющийся регламент, отображаются его название и дата. Изменения календаря обслуживания и журнала ТО подключены к Realtime, поэтому монитор обновляется без ручной перезагрузки страницы.

### Совместимость

Поле `next_service_date` оставлено и продолжает поддерживаться. Новые поля повторяющегося обслуживания добавлены в конец view `production_equipment_monitor`, чтобы не менять существующий порядок и контракт уже используемых колонок.

## Новые поля read model

- `maintenance_plan_id`
- `maintenance_plan_title`
- `maintenance_plan_type`
- `maintenance_plan_due_date`
- `maintenance_remind_before_days`

## Результат

Календарь ТО, журнал выполненных работ и производственный монитор теперь работают как единая цепочка: регламент → предупреждение → выполнение → перенос следующего срока → автоматическое обновление контроля.
