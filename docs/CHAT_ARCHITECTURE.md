# Единый чат A4PRINT HUB

## Что считается канонической реализацией

В системе больше нет отдельного приложения «Чат» и отдельных полноэкранных реализаций для персонала и партнёров.

Единственное ядро сообщений:

- `shared/hub-chat-core.js` — данные, контакты, сообщения, realtime, вложения, read-state;
- `shared/hub-chat.css` — базовый интерфейс;
- `shared/hub-chat-enhance.js` / `shared/hub-chat-enhance.css` — расширения для сотрудников;
- `shared/hub-chat-drawer.js` / `shared/hub-chat-drawer.css` — встроенная оболочка мессенджера внутри HUB/CRM.

## Персонал

Защищённые страницы `admin/` получают единый мессенджер через `admin/guard.js`.

Любая ссылка на старый `messages.html` должна открывать `#hub-chat`, а не отдельную страницу. `admin/messages.html` существует только как совместимый redirect для старых закладок и внешних ссылок.

## Партнёры

CRM партнёра подключает сообщения через:

`partner/config.js` → `partner/hub-chat.js` → `shared/hub-chat-drawer.js`.

Для партнёра показывается его рабочий диалог с HUB. `partner/crm-messages.html` остаётся только redirect-совместимостью.

## База данных

Актуальная модель единого чата задаётся миграциями:

- `database/migrations/20260913_unified_hub_chat.sql`;
- `database/migrations/20260913_unified_hub_chat_attachments.sql`.

Старые миграции чата не удалять: это история схемы БД, а не фронтенд-мусор.

## Правила дальнейшей разработки

1. Не создавать новое приложение/страницу Chat.
2. Не копировать логику сообщений в `admin/` или `partner/`; общая логика живёт в `shared/`.
3. Любая новая точка входа должна открывать `window.A4HubChat.open()` либо ссылку `#hub-chat`.
4. Счётчик непрочитанных, realtime и вложения не дублировать отдельными реализациями.
5. Сначала менять общее ядро, затем при необходимости добавлять небольшой context-specific adapter.
