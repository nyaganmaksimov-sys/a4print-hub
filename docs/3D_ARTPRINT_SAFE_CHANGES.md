# Безопасная разработка 3D-ARTPRINT в A4PRINT HUB

## Границы систем

- **A4PRINT HUB** — управление бизнесом. **A4PRINT KASSA** — отдельная кассовая система, интегрированная с HUB. Не считать их одним приложением.
- **3D-ARTPRINT** — веб-кабинет в составе HUB. Никакой необходимости в EXE/desktop для его работы нет.
- Изменения для 3D-ARTPRINT по умолчанию ограничены `admin/3d-artprint*`, `admin/assets/3d-artprint/`, документацией и новыми, изолированными тестами. Любой выход за эти границы должен быть явно описан в PR.

## Правила, обязательные перед слиянием

1. Разработка в feature-ветке и PR; прямые изменения в `main` запрещены.
2. **Не менять** `kassa/`, `desktop-kassa/`, кассовые маршруты/API, механизмы фискализации, смен, оплаты, синхронизации с МойСклад без отдельного согласования и отдельного PR.
3. **Не менять** общие файлы `admin/guard.js`, `admin/config.js`, глобальную навигацию или общие стили ради оформления 3D-ARTPRINT. Использовать локальные классы и CSS, в том числе для тёмной боковой панели.
4. Любое изменение схемы Supabase: отдельная миграция; сначала проверка схемы, RLS и tenant isolation на тестовом окружении. **Не применять миграцию к рабочей базе до проверки и отдельного разрешения.**
5. Не добавлять тестовые заказы, смены или платежи в производственную базу. Ни один автоматический тест не должен проводить реальные кассовые операции.
6. Для изменений 3D-ARTPRINT обязательны: синтаксис JS; доступность страницы и PNG/CSS; авторизация; видимость только разрешённых организаций; четыре физические карточки принтеров (две записи профилей Kobra X не означают два актива).
7. При затрагивании общих модулей обязательны регрессионные проверки кассы **в безопасном тестовом контуре**: вход оператора, открытие/закрытие тестовой смены, тестовый заказ, формирование тестового чека, синхронизация с МойСклад. До подтверждения не сливать.
8. Перед деплоем: резервная копия, проверка отката и журнал изменений. Деплой выполняется отдельно от merge и только с подтверждённым планом восстановления.
9. Если проверка не выполнена или среда недоступна — честно обозначить статус; успешные GitHub Actions не заменяют браузерный и регрессионный тест.
10. При подозрении на влияние на кассу: остановить выкладку, оценить объём затронутых файлов, откатить проблемный релиз по проверенной процедуре.

## Чек-лист PR для 3D-ARTPRINT

- [ ] Изменения ограничены файлами модуля
- [ ] Общие HUB файлы и касса не затронуты
- [ ] JS/HTML/CSS проверены и локальная тёмная тема не меняет другие страницы
- [ ] Не использованы фиктивные данные о состоянии принтеров или заказах
- [ ] Авторизация и RLS проверены по организациям и ролям
- [ ] PNG и логотип загружаются с правильных путей
- [ ] Все обязательные CI-проверки зелёные
- [ ] Если затронута общая инфраструктура — пройден тестовый кассовый сценарий
- [ ] Согласован план публикации и отката
