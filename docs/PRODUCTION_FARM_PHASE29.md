# Production Farm — Phase 29: исправленная проводка после сторно

Phase 29 закрывает следующий шаг после Phase 28: если исходная финансовая проводка была сторнирована, HUB может создать одну отдельную исправленную проводку, не меняя и не удаляя старую историю.

## Финансовая цепочка

История требования становится трёхступенчатой:

1. исходная операция Phase 27 — `EQUIPMENT_CONDITION_CLAIM`;
2. сторно Phase 28 — `EQUIPMENT_CONDITION_CLAIM_REVERSAL`;
3. исправленная операция Phase 29 — `EQUIPMENT_CONDITION_CLAIM_REPOST`.

Оригинал и сторно в сумме дают нулевой эффект. После repost действующий финансовый эффект формирует только исправленная операция.

## Ограничения

Исправленная проводка разрешена только для `SETTLED` claim и только если уже существует валидная пара «исходная операция + сторно». Repost без сторно запрещён.

Сумма исправленной проводки не вводится оператором и берётся из `settled_amount`. Для `HUB_TO_OWNER` и `OWNER_TO_HUB` финансовое направление фиксировано сервером; только для `MUTUAL` направление выбирается явно.

Оператор может выбрать другой активный cash account, но только внутри той же организации и той же валюты. Повторный repost по одному claim запрещён уникальными ограничениями.

## Audit

Таблица `equipment_condition_claim_financial_reposts` хранит:

- claim;
- ссылку на сторно;
- id исправленной cash transaction;
- обязательную причину;
- документ-основание;
- сотрудника и время.

Таблица append-only: update/delete блокируются триггером `CONDITION_CLAIM_FINANCIAL_REPOST_APPEND_ONLY`.

## Права и безопасность

Для preflight и создания repost одновременно нужны:

- `equipment.contracts.manage`;
- `production.settlements.manage`.

Новые RPC используют `SECURITY DEFINER`, `set search_path=''`, проверяют `auth.uid()` и внутренние permissions. `anon` не имеет EXECUTE. Таблица включена в RLS; клиенту разрешён только SELECT по staff-policy, прямые INSERT/UPDATE/DELETE закрыты.

## HUB UI

Экран `admin/equipment-condition-claim-reversals.html` теперь показывает состояния:

- активная исходная проводка;
- сторнирована;
- исправлена.

После сторно появляется действие `Исправить проводку`. Preflight показывает организацию, согласованную сумму и доступные счета нужной валюты. Оригинал и сторно из интерфейса не редактируются.

## Кабинет владельца

Вкладка `Финансовые корректировки` показывает владельцу безопасную цепочку: исходное направление, сторно и, если есть, текущую исправленную операцию. Внутренние названия cash account владельцу не раскрываются.
