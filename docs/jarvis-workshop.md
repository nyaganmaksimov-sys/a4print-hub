# Джарвис для цеха — v1

## Цель

Добавить в A4PRINT HUB визуальный контроль оборудования через IP-камеры и локальный edge-компьютер. Первая версия только наблюдает, классифицирует состояние и создаёт события. Управление станками добавляется отдельным этапом после проверки безопасности.

## Архитектура

```text
IP-камера (RTSP/ONVIF)
        │
        ▼
Edge Agent в цехе
- захват кадров
- health-check камеры
- локальная очередь
- детектор состояния
- снимок события
        │ HTTPS
        ▼
A4PRINT HUB / Supabase
- workshop_devices
- workshop_cameras
- workshop_events
- workshop_device_status
        │
        ▼
Admin: Джарвис · Цех
- живое состояние
- текущий заказ/задание
- последние события
- тревоги
```

## Первый стенд

1. Одна камера с RTSP/ONVIF над первым станком.
2. Один edge-компьютер в локальной сети цеха.
3. Первый объект наблюдения: 3D-принтер FlashForge AD5X.
4. Без удалённого выключения/старта в v1.

## Edge-компьютер

Предпочтительный вариант для компьютерного зрения: NVIDIA Jetson Orin Nano Super 8GB + NVMe. Допустимый бюджетный вариант для первого прототипа без тяжёлой локальной модели: mini-PC Intel N100/N150 с 16GB RAM и NVMe.

## Камера

Требования:
- RTSP;
- ONVIF;
- 1080p или 4MP;
- стабильная работа по Ethernet, желательно PoE;
- фиксированное положение;
- ночной режим отключаемый, если ИК-подсветка мешает видеть дисплей станка.

## Состояния оборудования

- OFFLINE — устройство/камера недоступны;
- IDLE — оборудование включено, но не выполняет задание;
- RUNNING — идёт работа;
- PAUSED — пауза;
- DONE — задача визуально завершена;
- WARNING — требует внимания;
- ERROR — подтверждённая остановка/ошибка.

## Типы событий

- camera_offline;
- camera_online;
- device_started;
- device_stopped;
- device_idle;
- job_completed;
- visual_warning;
- visual_error;
- print_detached;
- filament_issue;
- operator_present;
- unknown_change.

## Безопасность

RTSP-пароли и токены камер не хранятся в GitHub и не передаются в браузер. Edge Agent хранит секреты локально. HUB получает только heartbeat, состояния, события и при необходимости снимки. Управляющие команды в первой версии отсутствуют.

## Интеграция с производством

`workshop_device_status.production_job_id` позволяет связать станок с `production_jobs`. После подтверждения логики можно автоматически переводить производственное задание в IN_PROGRESS / PAUSED / DONE, но только после периода наблюдения без автодействий.
