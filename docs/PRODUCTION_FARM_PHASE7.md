# Производственная ферма — этап 7

Этап 7 добавляет реальный календарь мощности оборудования и безопасное планирование производственных заданий. Он использует существующие `equipment_assets` и `production_jobs`; отдельная очередь или параллельная модель заданий не создаётся.

## Календарь мощности

Добавлена таблица `equipment_capacity_rules` с доступной мощностью каждого станка по дням недели.

Для существующего оборудования автоматически создаётся стартовый график, равный прежней управленческой модели:

- понедельник–пятница — 480 минут в день;
- суббота–воскресенье — 0 минут.

Это только начальные значения. В интерфейсе производства их можно изменить отдельно для каждого станка.

Новые единицы оборудования получают такой же стартовый недельный график автоматически.

## Планирование заданий

Добавлен RPC `schedule_production_job(...)`. Он:

- требует `production.manage`;
- работает только с открытыми заданиями `NEW`, `QUEUED`, `PAUSED`;
- проверяет существование и доступность станка;
- записывает `equipment_id`, `planned_start`, `planned_end`;
- переводит новое задание в `QUEUED`;
- если `planned_machine_minutes` ещё не заполнено, рассчитывает его по длительности окна;
- блокирует пересекающиеся окна на одном физическом станке.

Проверка пересечений выполняется не только внутри RPC. На `production_jobs` установлен серверный trigger `validate_production_job_schedule`, поэтому пересечение блокируется и при изменении задания через старый интерфейс или прямую запись.

Для конкурентных изменений используется транзакционная advisory-блокировка по `equipment_id`, чтобы два параллельных запроса не смогли занять одно и то же окно одновременно.

## Мощность и перегруз

RPC `production_capacity_between(p_from, p_to)` возвращает по каждому станку и дню:

- доступные минуты;
- уже зарезервированные минуты;
- процент загрузки;
- число запланированных заданий;
- признак перегруза.

Диапазон ограничен 400 днями, чтобы случайный тяжёлый запрос не создавал лишнюю нагрузку на рабочую базу.

Задание может сознательно создать перегруз дня — например, при сверхурочной работе. Такой случай не блокируется, но явно подсвечивается в интерфейсе. Жёстко блокируется именно физическое пересечение временных окон на одном станке.

## Интерфейс

В `admin/production.html` подключён модуль **«📅 План загрузки»**.

В нём можно:

- смотреть горизонт 7, 14 или 30 дней;
- видеть загрузку каждого станка по дням;
- видеть перегруженные дни;
- видеть задания без полного плана;
- назначать станок и временное окно;
- настраивать доступные часы для каждого дня недели;
- получать понятное сообщение при попытке поставить два задания на один станок одновременно.

Интерфейс работает и на мобильном экране.

## Связь с экономикой фермы

Модуль `equipment-economics.js` больше не использует условную формулу «8 часов × рабочий день» для выбранных периодов 30/90/365 дней.

Загрузка рассчитывается как:

`фактическое машинное время / доступные минуты из календаря мощности`.

Таким образом, изменение графика конкретного станка автоматически меняет его показатель загрузки в экономике оборудования.

Для режима «Всё время» процент загрузки не рассчитывается, потому что календарь мощности является текущей управленческой настройкой и не хранит исторические версии графика.

## Безопасность

- `equipment_capacity_rules` защищена RLS;
- браузеру разрешено только чтение правил;
- изменение графика выполняется через permission-checked RPC `save_equipment_capacity(...)`;
- trigger-хелперы недоступны как публичные RPC;
- планирование выполняется через `schedule_production_job(...)` с проверкой права `production.manage`;
- правила мощности и изменения планирования продолжают попадать в существующий аудит там, где используется общий механизм `audit_row_change`.

## Проверка рабочей БД

После применения миграции выполнена проверка под действующим пользователем с правами ADMIN.

Подтверждено:

- для существующего Epson L805 создано 7 правил мощности;
- на рабочих днях доступно по 480 минут, на выходных — 0;
- `production_capacity_between(...)` возвращает календарь без ошибок;
- тестовое задание успешно планируется и переходит `NEW → QUEUED`;
- при отсутствии `planned_machine_minutes` длительность окна записывается как плановое машинное время;
- второе тестовое задание с пересекающимся окном получает `EQUIPMENT_PLAN_OVERLAP`;
- изменение недельной мощности через `save_equipment_capacity(...)` проходит под `production.manage`;
- весь write-тест выполнен в транзакции и полностью откатан.
