# Production Farm Phase 23 — осмотры состояния оборудования

Phase 23 фиксирует физическое состояние партнёрского оборудования при приёмке, возврате и периодических проверках. Цель — иметь аудируемый снимок состояния, комплектности, дефектов и фото, а не выяснять состояние оборудования задним числом.

## Типы осмотров

- `ACCEPTANCE` — приёмка оборудования в работу HUB;
- `RETURN` — осмотр перед возвратом владельцу;
- `PERIODIC` — промежуточная проверка состояния.

Осмотр содержит дату и место, показания счётчика/наработки, общую оценку состояния, работоспособность, структурированный чек-лист, список дефектов, примечания и приложенные файлы.

## Чек-лист и фотофиксация

Чек-лист обязателен и использует результаты `PASS`, `ISSUE`, `NA`. В интерфейсе HUB базовый набор включает внешний вид, питание, механику, безопасность и комплектность.

Для `ACCEPTANCE` и `RETURN` минимум одна фотография обязательна. Если есть замечание чек-листа, состояние `POOR`/`NON_OPERATIONAL` или работоспособность не `READY`, завершить акт без описанного дефекта нельзя.

Файлы хранятся в `hub-documents` под `equipment-inspections/<inspection_id>/...`; метаданные фиксируются в `equipment_condition_inspection_files`.

## Неизменяемость

После `COMPLETED` сам осмотр нельзя обновить или удалить (`COMPLETED_INSPECTION_IMMUTABLE`). Список его файлов также становится неизменяемым (`COMPLETED_INSPECTION_FILES_IMMUTABLE`). Исправление фактической ошибки должно оформляться новым документированным действием, а не переписыванием старого акта.

При завершении создаётся центральный документ типа `EQ_CONDITION_INSPECTION` со snapshot оборудования, владельца, договора, результатов осмотра и списка файлов. Документ связывается через `document_links` с осмотром, оборудованием, договором, партнёром и, для возврата, с процедурой расторжения.

## Связь с расторжением

`RETURN` допускается только при открытой процедуре расторжения `NOTICE`, `PREPARING` или `READY` и обязательно привязан к конкретному `termination_id`.

Триггер `guard_equipment_termination_return_inspections()` не позволяет перевести расторжение в `COMPLETED`, пока по каждой единице оборудования договора нет завершённого возвратного осмотра именно в рамках этого расторжения. Ошибка: `RETURN_INSPECTION_REQUIRED`.

## Доступ владельца

Партнёрский RPC `get_my_equipment_condition_inspections()` определяет владельца через `current_partner_id()` и публикует только собственные осмотры со статусом `COMPLETED`. Черновики и отменённые записи владельцу не выдаются.

В кабинете владельца вкладка «Осмотры состояния» показывает акт, чек-лист, дефекты, состояние и фото. Доступ к файлам защищён storage-policy `hub_documents_equipment_partner_inspection_read`: подписанный URL может получить только владелец завершённого осмотра своего оборудования.

## HUB

`admin/equipment-condition-inspections.html` предоставляет:

- KPI черновиков, отсутствующих приёмок, ожидающих возвратных осмотров и актов с дефектами;
- создание и редактирование черновика;
- загрузку фото/PDF до 50 МБ на файл;
- завершение или отмену черновика;
- просмотр чек-листа, дефектов и фото;
- фильтрацию по типу, статусу, партнёру, договору и оборудованию.

В навигации HUB раздел доступен как «Осмотры состояния» рядом с оборудованием.

## Безопасность

Browser RPC доступны только `authenticated`, anon EXECUTE отсутствует. Управляющие действия требуют `equipment.manage`. Внутренние validation/guard функции недоступны browser roles. SECURITY DEFINER функции используют пустой `search_path`.

RLS разрешает владельцу читать только собственные завершённые осмотры и их файлы; сотрудники HUB используют существующие equipment permissions.
