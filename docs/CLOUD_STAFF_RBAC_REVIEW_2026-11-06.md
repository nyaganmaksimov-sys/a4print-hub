# A4PRINT Cloud — проверка ролей перед включением сотрудников

**Дата проверки:** 6 ноября 2026 года. **Среда:** Neon `A4PRINT-Cloud-STAGING`, только тестовая. Оригинальная Supabase не изменена.

## Что перенесено

| Источник Supabase | Таблица в Neon | Строки | Сверка |
|---|---|---:|---|
| `public.roles` | `migration_review.roles` | 7 | Совпала MD5 всех записей |
| `public.permissions` | `migration_review.permissions` | 12 | Совпала MD5 всех записей |
| `public.role_permissions` | `migration_review.role_permissions` | 32 | Совпала MD5 всех записей |
| `public.user_roles` | `migration_review.staff_role_assignments` | 28 | Совпала MD5 всех записей с переименованными ключами |

Все UUID сохранены; связей с отсутствующими профилями, ролями или разрешениями нет. Данные скопированы один раз, **не синхронизируются в реальном времени**.

## Матрица старых ролей — нужна проверка

| Роль | Число назначений | Связанных разрешений |
|---|---:|---:|
| ADMIN | 4 | 12 |
| MANAGER | 6 | 12 |
| POS_OPERATOR | 6 | 0 |
| PRODUCTION | 6 | 3 |
| WAREHOUSE | 6 | 2 |
| VIEWER | 0 | 3 |
| SUPPORT | 0 | 0 |

**Высокий риск чрезмерных прав:** `MANAGER` назначен всем шести профилям и связан со всеми 12 разрешениями; `ADMIN` назначен четырём. Новая система **не должна** автоматически выдавать эти роли. Ноль записей в `role_permissions` для `POS_OPERATOR` не доказывает отсутствие доступа: часть прав может проверяться напрямую в коде, это надо исследовать отдельно.

## Текущее состояние новых аккаунтов

- Четыре профиля ожидают новой учётной записи Neon Auth и нового пароля.
- Два профиля не имеют прежней связи с Supabase Auth и требуют ручного сопоставления.
- Никаких реальных Neon Auth аккаунтов сотрудников не создано, подтверждённых назначений нет, активных разрешений нет.
- Тестовый Render API не имеет прав даже читать закрытый `migration_review`.

## Предохранители перед подключением

`migration_review.staff_role_reviews` — отдельная таблица подтверждений по каждой паре сотрудник–роль. Сейчас пустая. `migration_review.staff_identity_review_status` показывает причины блокировки (4 `NEEDS_NEON_ACCOUNT`, 2 `NEEDS_IDENTITY_RECONCILIATION`). Это **только отчёт**, не источник прав на вход.

`cloud_staging_session_grants` дополнительно защищён триггером: даже владелец базы не сможет ошибочно использовать его для реального сотрудника. Допускаются только специально созданные синтетические `a4print-staging-*\@example.com` аккаунты. Все существующие тестовые разрешения остаются отключёнными.

Проверено реальной PostgreSQL 17:
- Миграции `006` и `007` применяются повторно без повреждения схемы.
- Клиентские роли и Render не могут читать закрытые таблицы ролей.
- Попытка добавить обычного пользователя в синтетические разрешения отклоняется.
- Ни одно разрешение не появляется автоматически.

[Успешный прогон GitHub Actions — Check Cloud RBAC Review Gate](https://github.com/nyaganmaksimov-sys/a4print-hub/actions/runs/42270407817).

## Контрольные запросы без персональных данных

```sql
SELECT blocker, COUNT(*) AS profiles
FROM migration_review.staff_identity_review_status
GROUP BY blocker ORDER BY blocker;

SELECT count(*) AS approvals FROM migration_review.staff_role_reviews;

SELECT count(*) AS active_test_grants
FROM public.cloud_staging_session_grants WHERE enabled;
```

## Что ещё сделать до запуска

1. Лично подтвердить список сотрудников, какие профили используются, и кто имеет права администратора. Отдельно проверить прежнюю широкую роль `MANAGER`.
2. Создать рабочие учётные записи через Neon Auth с установкой новых паролей сотрудниками. Пароли Supabase Auth не мигрируют.
3. Зафиксировать проверенную связь Neon Auth UUID → старый профиль и отдельно утвердить **минимальные** рабочие роли.
4. Реализовать серверные проверки разрешений и принадлежности организации для рабочих маршрутов HUB и кассы, включая отзыв сессий.
5. Перенести остальные зависимости API (таблицы, функции, Storage) и проверить PIN, смены, возвраты, офлайн-очередь и недублирование чеков.
6. Перед переключением сделать новую сверку данных, поскольку исходная Supabase остаётся активным источником.

**Это не готовый рабочий вход:** архив старых прав нельзя использовать для выдачи действующих разрешений автоматически.

Код: `api/cloud-staging/sql/006_rbac_review_snapshot.sql`, `api/cloud-staging/sql/007_staff_review_gate.sql`.
